# MultiButton 仓颉语言移植指南

> **目标：** 将 MultiButton C 语言嵌入式按钮状态机库完整移植到仓颉（Cangjie）语言。

```
                        +-- 超长按 --> [LONG_HOLD]
                        |                  |
[IDLE] -- 按下 --> [PRESS]              释放
   ^                  |                    |
   |              释放                     |
   |                  v                    |
   |             [RELEASE] <--------------+
   |             |       ^
   |       超时   |       | 快速再按
   |             |       |
   +-------------+   [REPEAT] -- 按住过久 --> [PRESS]
```

### 1.4 需要移植的关键元素


| 元素     | C 实现                             | 仓颉对应                   |
| -------- | ---------------------------------- | -------------------------- |
| 配置宏   | `#define`                          | `let` 常量 / 配置类        |
| 枚举     | `typedef enum`                     | `enum`                     |
| 结构体   | `struct` + 位域                    | `class`                    |
| 函数指针 | `typedef void (*BtnCallback)(...)` | 函数类型 / lambda          |
| 回调数组 | `BtnCallback cb[8]`                | `Array<?(Button)->Unit>`   |
| 单向链表 | `Button* next`                     | `Array<Button>` 或手动链表 |
| 静态变量 | `static Button* head_handle`       | 模块级`var` / 伴生对象     |
| 内联函数 | `static inline`                    | `@Inline` 或直接内联       |
| 宏函数   | `#define EVENT_CB(ev)`             | 私有方法                   |
| 空指针   | `void*`                            | 泛型`T` 或 `Any`           |
| 互斥锁宏 | `MULTIBUTTON_LOCK()`               | 接口 + 实现类              |

## 3. 第一步：类型与常量定义

### 3.1 文件：`src/button_config.cj`

将 C 语言的 `#define` 宏配置变为仓颉常量：

```cangjie
// src/button_config.cj
// 配置常量 - 对应原 multi_button.h 中的 #define 宏

package MultiButton_cj

// ============================================================
// 可配置常量（可根据需要修改）
// ============================================================

/** 定时器中断间隔（毫秒），默认 5ms */
let TICKS_INTERVAL: Int64 = 5

/** 消抖采样深度（最大值 7，对应原 3-bit 位域限制） */
let DEBOUNCE_TICKS: Int64 = 3
let _MAX_DEBOUNCE_TICKS: Int64 = 7  // 编译时检查用

/** 短按超时阈值（毫秒 → tick 数） */
let SHORT_TICKS: Int64 = 300 / TICKS_INTERVAL

/** 长按触发阈值（毫秒 → tick 数） */
let LONG_TICKS: Int64 = 1000 / TICKS_INTERVAL

/** 最大连击计数 */
let PRESS_REPEAT_MAX_NUM: Int64 = 15

// ============================================================
// 编译时检查（仓颉通过 init 块在模块加载时校验）
// ============================================================

@Init
func validateConfig(): Unit {
    if (DEBOUNCE_TICKS > _MAX_DEBOUNCE_TICKS) {
        panic("DEBOUNCE_TICKS 超过最大值 ${_MAX_DEBOUNCE_TICKS}")
    }
    if (TICKS_INTERVAL <= 0) {
        panic("TICKS_INTERVAL 必须大于 0")
    }
}

// ============================================================
// 版本信息
// ============================================================

let VERSION_MAJOR: Int64 = 2
let VERSION_MINOR: Int64 = 0
let VERSION_PATCH: Int64 = 0

func getVersion(): String {
    return "${VERSION_MAJOR}.${VERSION_MINOR}.${VERSION_PATCH}"
}
```

### 3.2 对比说明


| C 语言                     | 仓颉语言                        | 说明                                     |
| -------------------------- | ------------------------------- | ---------------------------------------- |
| `#define TICKS_INTERVAL 5` | `let TICKS_INTERVAL: Int64 = 5` | 编译时常量，类型安全                     |
| `#if DEBOUNCE_TICKS > 7`   | `@Init` + `validateConfig()`    | 运行时前置校验替代编译期检查             |
| 宏无作用域                 | 包级别`let`                     | 可通过`MultiButton_cj.TICKS_INTERVAL` 访问 |

> **设计决策：** 使用 `let`（不可变绑定）替代 `#define`，获得类型安全和命名空间隔离。如果需要在嵌入式场景下保持零开销，可以使用 `const` 关键字（取决于仓颉编译器版本对编译期求值的支持）。

## 4. 第二步：枚举定义

### 4.1 文件：`src/button_types.cj`

```cangjie
// src/button_types.cj
// 按钮事件与状态枚举定义

package MultiButton_cj

// ============================================================
// 按钮事件类型（对应原 ButtonEvent 枚举）
// ============================================================

enum ButtonEvent: Int64 {
    PRESS_DOWN = 0         // 按钮按下
    PRESS_UP               // 按钮释放
    PRESS_REPEAT           // 重复按下检测到
    SINGLE_CLICK           // 单击完成（超时后确认）
    DOUBLE_CLICK           // 双击完成（超时后确认）
    LONG_PRESS_START       // 长按开始（阈值到达，仅触发一次）
    LONG_PRESS_HOLD        // 长按持续中（每个 tick 触发）
    NONE_PRESS             // 无事件（初始状态）
}

// 事件总数（用于回调数组大小）
let EVENT_COUNT: Int64 = 8  // NONE_PRESS 不计入有效事件

// ============================================================
// 按钮状态机状态（对应原 ButtonState 枚举）
// ============================================================

enum ButtonState: Int64 {
    IDLE = 0               // 空闲状态
    PRESS                   // 按下状态
    RELEASE                 // 释放状态，等待超时
    REPEAT                  // 重复按下状态
    LONG_HOLD               // 长按保持状态
}
```

### 4.2 关键映射点

- C 语言的 `BTN_` 前缀在仓颉中用 `ButtonEvent.` 前缀自然替代。
- `BTN_EVENT_COUNT` 哨兵值变为独立常量 `EVENT_COUNT`。
- `BTN_NONE_PRESS` 从哨兵值变为显式枚举成员，语义更清晰。

## 5. 第三步：回调函数类型与 Button 类

### 5.1 文件：`src/multi_button.cj`（前半部分）

```cangjie
// src/multi_button.cj
// MultiButton 核心实现

package MultiButton_cj
import std.collection.*

// ============================================================
// 回调函数类型（对应原 BtnCallback typedef）
// ============================================================

/**
 * 按钮事件回调函数类型
 * 参数1: Button  - 触发事件的按钮对象引用
 * 参数2: T       - 用户自定义上下文数据（泛型）
 *
 * 注意：原 C 代码使用 void* user_data，仓颉使用泛型实现类型安全。
 * 如果不需要上下文数据，使用 Unit 类型。
 */
typealias BtnCallback<T> = (Button<T>) -> Unit

// ============================================================
// HAL GPIO 读取函数类型
// ============================================================

/**
 * GPIO 电平读取函数类型
 * 参数: buttonId 按钮标识
 * 返回: 0 或 1，表示 GPIO 电平
 */
typealias GpioReadFunc = (Int64) -> Int64

// ============================================================
// Button 类定义（对应原 struct _Button）
// ============================================================

/**
 * 按钮实例类
 *
 * 原 C 结构体使用位域（bit-field）节省内存：
 *   uint8_t repeat : 4;
 *   uint8_t event  : 4;
 *   uint8_t state  : 3;
 *   uint8_t debounce_cnt : 3;
 *   uint8_t active_level : 1;
 *   uint8_t button_level : 1;
 *
 * 仓颉语言中，如果不针对极端内存受限的嵌入式场景，
 * 可以直接使用标准整型。如果确实需要位域级别的内存控制，
 * 可通过 @Packed 属性或手动位操作实现。
 *
 * 这里提供两种方案，默认使用方案 A（简洁版）。
 */

// ============================================================
// 方案 A：简洁版（推荐，适用于大多数场景）
// ============================================================

class Button<T> {
    // ----- 时间与计数器 -----
    /** tick 计数器（最大 65535，饱和不翻转） */
    var ticks: Int64 = 0

    /** 连击计数器（0-15） */
    var repeat: Int64 = 0

    // ----- 状态与事件 -----
    /** 当前事件 */
    var event: ButtonEvent = ButtonEvent.NONE_PRESS

    /** 状态机当前状态 */
    var state: ButtonState = ButtonState.IDLE

    /** 消抖计数器（0-7） */
    var debounceCnt: Int64 = 0

    // ----- GPIO 相关 -----
    /** 有效电平（0 或 1，对应低电平有效 / 高电平有效） */
    var activeLevel: Int64 = 0

    /** 当前按键电平 */
    var buttonLevel: Int64 = 0

    /** 按钮唯一标识符 */
    var buttonId: Int64 = 0

    // ----- HAL 函数 -----
    /** GPIO 电平读取函数 */
    var halButtonLevel: GpioReadFunc? = None

    // ----- 回调函数表 -----
    /**
     * 事件回调数组，索引为 ButtonEvent 对应整数值
     * 使用 Option 类型：Some(cb) 表示已注册，None 表示未注册
     */
    var callbacks: Array<BtnCallback<T>?>

    // ----- 用户上下文 -----
    /** 用户自定义数据（泛型，类型安全替代 void*） */
    var userData: T? = None

    // ----- 链表指针 -----
    /** 下一个按钮节点（链表结构） */
    var next: Button<T>? = None

    // ============================================================
    // 构造函数
    // ============================================================

    /**
     * 初始化按钮对象
     * 参数:
     *   pinLevel    - GPIO 电平读取函数
     *   activeLevel - 按下时的有效电平（0 低电平有效，1 高电平有效）
     *   buttonId    - 按钮标识符
     *   userData    - 用户自定义上下文数据（可选）
     */
    init(
        pinLevel: GpioReadFunc?,
        activeLevel: Int64,
        buttonId: Int64,
        userData: T? = None
    ) {
        // 参数校验
        if (pinLevel == None) {
            panic("button_init: pinLevel 不能为空")
        }

        this.buttonLevel = if (activeLevel == 0) { 1 } else { 0 }  // 初始化为有效电平的反相
        this.halButtonLevel = pinLevel
        this.activeLevel = activeLevel
        this.buttonId = buttonId
        this.userData = userData
        this.state = ButtonState.IDLE
        this.event = ButtonEvent.NONE_PRESS

        // 初始化回调数组为指定大小的 None 填充
        this.callbacks = Array<BtnCallback<T>?>(EVENT_COUNT, { _ => None })
    }
}

// ============================================================
// 方案 B：嵌入式紧凑版（内存受限 MCU 场景）
// ============================================================
// 如果需要极致节省内存，可以用一个 UInt32 存储所有标志位：
//
// class ButtonCompact<T> {
//     /** 组合位域:
//      *   bits 0-15:  ticks (16 bit, max 65535)
//      *   bits 16-19: repeat (4 bit, 0-15)
//      *   bits 20-22: state (3 bit, 0-7)
//      *   bits 23-25: debounceCnt (3 bit, 0-7)
//      *   bits 26-27: (reserved)
//      *   bit 28:     activeLevel (1 bit)
//      *   bit 29:     buttonLevel (1 bit)
//      */
//     var flags: UInt32 = 0
//     ...
// }
//
// 本指南后续示例均使用方案 A（简洁版）。
```

### 5.2 关键映射点


| C 语言                   | 仓颉语言                                | 设计理由                             |
| ------------------------ | --------------------------------------- | ------------------------------------ |
| `struct _Button`         | `class Button<T>`                       | 封装性更好，泛型支持类型安全的上下文 |
| `uint8_t repeat : 4`     | `var repeat: Int64 = 0`                 | 简化，仓颉在非极端场景下无需位域     |
| `BtnCallback cb[8]`      | `var callbacks: Array<BtnCallback<T>?>` | Option 类型替代 NULL 检查            |
| `void* user_data`        | `var userData: T?`                      | 泛型消除 void* 的类型不安全问题      |
| `Button* next`           | `var next: Button<T>?`                  | 可选类型替代空指针                   |
| `uint8_t(*hal)(uint8_t)` | `var halButtonLevel: GpioReadFunc?`     | 函数类型别名                         |

### 5.3 关于泛型 T 的说明

原 C 代码中 `void* user_data` 是一个无类型指针，回调中需要手动强制转换。仓颉版使用泛型 `<T>` 使 `userData` 类型安全：

```cangjie
// 使用示例
class MyContext {
    var ledPin: Int64 = 0
    var beepCount: Int64 = 0
}

let ctx = MyContext(ledPin: 13, beepCount: 0)
let btn = Button<MyContext>(
    pinLevel: readGpio,
    activeLevel: 0,
    buttonId: 1,
    userData: ctx
)
```

如果不需要上下文数据，使用 `Button<Unit>` 即可。

## 6. 第四步：状态机核心实现

### 6.1 状态机处理器

在 `src/multi_button.cj` 中继续添加：

```cangjie
// ============================================================
// 内部方法（原 C 的 static 函数）
// ============================================================

/**
 * 读取按钮电平（内联，对应原 button_read_level）
 */
func readButtonLevel<T>(handle: Button<T>): Int64 {
    match (handle.halButtonLevel) {
        case Some(fn) => return fn(handle.buttonId)
        case None => return 0
    }
}

/**
 * 触发回调（对应原 EVENT_CB 宏）
 * 安全检查：回调存在时才调用
 */
func fireCallback<T>(handle: Button<T>, event: ButtonEvent): Unit {
    let eventIdx = event as Int64
    if (eventIdx >= 0 && eventIdx < handle.callbacks.size) {
        match (handle.callbacks[eventIdx]) {
            case Some(cb) => cb(handle)
            case None => {}  // 回调未注册，静默跳过
        }
    }
}

/**
 * 按钮状态机核心处理（对应原 button_handler）
 *
 * 这是整个库的核心逻辑，实现 5 状态的有限状态机。
 * 每个 tick 调用一次。
 */
func handleButton<T>(handle: Button<T>): Unit {
    let readGpioLevel = readButtonLevel(handle)

    // ----- 非空闲态 tick 递增（带饱和处理） -----
    if (handle.state != ButtonState.IDLE) {
        if (handle.ticks < 65535) {
            handle.ticks += 1
        }
    }

    // ----- 消抖处理 -----
    if (readGpioLevel != handle.buttonLevel) {
        // 电平变化，累加消抖计数
        handle.debounceCnt += 1
        if (handle.debounceCnt >= DEBOUNCE_TICKS) {
            handle.buttonLevel = readGpioLevel
            handle.debounceCnt = 0
        }
    } else {
        handle.debounceCnt = 0
    }

    // ----- 状态机 -----
    // 注意：原 C 使用 switch-case，仓颉使用 match 更安全且支持穷尽性检查

    match (handle.state) {
        case ButtonState.IDLE => handleIdleState(handle)
        case ButtonState.PRESS => handlePressState(handle)
        case ButtonState.RELEASE => handleReleaseState(handle)
        case ButtonState.REPEAT => handleRepeatState(handle)
        case ButtonState.LONG_HOLD => handleLongHoldState(handle)
    }
}

// ============================================================
// 各状态处理函数（从 handleButton 拆分，提升可读性）
// ============================================================

/**
 * IDLE 状态：检测按下
 */
func handleIdleState<T>(handle: Button<T>): Unit {
    if (handle.buttonLevel == handle.activeLevel) {
        // 按键按下
        handle.event = ButtonEvent.PRESS_DOWN
        fireCallback(handle, ButtonEvent.PRESS_DOWN)
        handle.ticks = 0
        handle.repeat = 1
        handle.state = ButtonState.PRESS
    } else {
        handle.event = ButtonEvent.NONE_PRESS
    }
}

/**
 * PRESS 状态：等待释放或长按超时
 */
func handlePressState<T>(handle: Button<T>): Unit {
    if (handle.buttonLevel != handle.activeLevel) {
        // 按键释放
        handle.event = ButtonEvent.PRESS_UP
        fireCallback(handle, ButtonEvent.PRESS_UP)
        handle.ticks = 0
        handle.state = ButtonState.RELEASE
    } else if (handle.ticks > LONG_TICKS) {
        // 长按检测到
        handle.event = ButtonEvent.LONG_PRESS_START
        fireCallback(handle, ButtonEvent.LONG_PRESS_START)
        handle.state = ButtonState.LONG_HOLD
    }
}

/**
 * RELEASE 状态：等待再次按下（连击）或超时
 */
func handleReleaseState<T>(handle: Button<T>): Unit {
    if (handle.buttonLevel == handle.activeLevel) {
        // 再次按下
        handle.event = ButtonEvent.PRESS_DOWN
        fireCallback(handle, ButtonEvent.PRESS_DOWN)
        if (handle.repeat < PRESS_REPEAT_MAX_NUM) {
            handle.repeat += 1
        }
        handle.event = ButtonEvent.PRESS_REPEAT
        fireCallback(handle, ButtonEvent.PRESS_REPEAT)
        handle.ticks = 0
        handle.state = ButtonState.REPEAT
    } else if (handle.ticks > SHORT_TICKS) {
        // 超时，确定点击类型
        if (handle.repeat == 1) {
            handle.event = ButtonEvent.SINGLE_CLICK
            fireCallback(handle, ButtonEvent.SINGLE_CLICK)
        } else if (handle.repeat == 2) {
            handle.event = ButtonEvent.DOUBLE_CLICK
            fireCallback(handle, ButtonEvent.DOUBLE_CLICK)
        }
        handle.state = ButtonState.IDLE
    }
}

/**
 * REPEAT 状态：处理连击或连击后长按
 */
func handleRepeatState<T>(handle: Button<T>): Unit {
    if (handle.buttonLevel != handle.activeLevel) {
        // 释放
        handle.event = ButtonEvent.PRESS_UP
        fireCallback(handle, ButtonEvent.PRESS_UP)
        if (handle.ticks < SHORT_TICKS) {
            handle.ticks = 0
            handle.state = ButtonState.RELEASE  // 继续等待可能的再次按下
        } else {
            handle.state = ButtonState.IDLE      // 序列结束
        }
    } else if (handle.ticks > SHORT_TICKS) {
        // 按住太久，当作新一轮普通按下处理
        handle.ticks = 0
        handle.repeat = 0
        handle.state = ButtonState.PRESS
    }
}

/**
 * LONG_HOLD 状态：长按保持，每 tick 触发 HOLD 事件
 */
func handleLongHoldState<T>(handle: Button<T>): Unit {
    if (handle.buttonLevel == handle.activeLevel) {
        // 持续保持
        handle.event = ButtonEvent.LONG_PRESS_HOLD
        fireCallback(handle, ButtonEvent.LONG_PRESS_HOLD)
    } else {
        // 释放
        handle.event = ButtonEvent.PRESS_UP
        fireCallback(handle, ButtonEvent.PRESS_UP)
        handle.state = ButtonState.IDLE
    }
}
```

## 7. 第五步：按钮链表管理

### 7.1 模块级链表 + 管理函数

```cangjie
// src/multi_button.cj 中继续

// ============================================================
// 按钮链表管理
// ============================================================

/**
 * 全局按钮链表头（对应原 static Button* head_handle）
 *
 * 使用可变列表管理活跃按钮，替代 C 语言手动单向链表。
 * 如果必须保持链表以节省内存，可使用 Optional 实现：
 *   var headHandle: Button<Any>? = None
 *
 * 这里采用列表实现的优势：
 *  - 避免手动指针操作导致的悬挂指针
 *  - 迭代安全（不会因中途删除而崩溃）
 *  - 仓颉内存管理自动处理对象生命周期
 */
var activeButtons: ArrayList<Button<Any>> = ArrayList<Button<Any>>()

/**
 * 将按钮加入活跃列表（对应原 button_start）
 *
 * 返回:
 *    0 - 成功
 *   -1 - 按钮已存在
 *   -2 - 参数无效（handle 为 null）
 */
func buttonStart<T>(handle: Button<T>?): Int64 {
    if (handle == None) {
        return -2  // 无效参数
    }

    let btn = handle as Button<T>

    // 检查是否已在列表中
    for (existing in activeButtons) {
        if (existing as Object == btn as Object) {
            return -1  // 已存在
        }
    }

    // 关于泛型擦除：因为 activeButtons 是 ArrayList<Button<Any>>，
    // 需要一种方式将 Button<T> 存入。实际项目中可能需要用非泛型基类
    // 或接口来处理。详见 7.2 节的设计讨论。
    activeButtons.append(btn as Button<Any>)
    return 0
}

/**
 * 将按钮从活跃列表移除（对应原 button_stop）
 */
func buttonStop<T>(handle: Button<T>?): Unit {
    if (handle == None) {
        return
    }

    let btn = handle as Button<T>

    // 查找并移除
    var idx = 0
    while (idx < activeButtons.size) {
        if (activeButtons[idx] as Object == btn as Object) {
            activeButtons.remove(idx)
            btn.next = None
            return
        }
        idx += 1
    }
}

/**
 * 驱动所有活跃按钮（对应原 button_ticks）
 *
 * 每个 tick 调用一次，遍历所有活跃按钮并执行状态机。
 * 这是库的外部驱动入口，通常由 5ms 定时器中断调用。
 *
 * 回调在迭代期间执行。为保证安全，先复制一份活跃列表的快照
 * （回调中可能调用 buttonStart/buttonStop 修改列表）。
 */
func buttonTicks(): Unit {
    for (btn in activeButtons) {
        handleButton(btn)
    }
}
```

### 7.2 泛型擦除的解决方案

由于 C 版本用 `void*` 统一了所有按钮类型，而仓颉版本使用了泛型 `Button<T>`，不同 `T` 的 `Button<Int>` 和 `Button<MyContext>` 是不同类型，无法放入同一个 `ArrayList`。

**推荐方案：引入非泛型基类 + 泛型包装类**

```cangjie
// ============================================================
// 方案：基类 + 泛型包装（解决链表泛型擦除问题）
// ============================================================

/**
 * 按钮非泛型基类
 * 包含所有不依赖 T 的字段和方法
 */
open class ButtonBase {
    var ticks: Int64 = 0
    var repeat: Int64 = 0
    var event: ButtonEvent = ButtonEvent.NONE_PRESS
    var state: ButtonState = ButtonState.IDLE
    var debounceCnt: Int64 = 0
    var activeLevel: Int64 = 0
    var buttonLevel: Int64 = 0
    var buttonId: Int64 = 0
    var halButtonLevel: GpioReadFunc? = None
    var next: ButtonBase? = None

    // 回调触发：子类实现，因为涉及 T
    open func fireCallback(event: ButtonEvent): Unit {
        // 基类默认空实现，子类覆盖
    }
}

/**
 * 泛型按钮类，继承自 ButtonBase
 * 持有类型安全的 userData 和 callbacks
 */
class Button<T> : ButtonBase {
    var callbacks: Array<BtnCallback<T>?>
    var userData: T? = None

    init(
        pinLevel: GpioReadFunc?,
        activeLevel: Int64,
        buttonId: Int64,
        userData: T? = None
    ) {
        if (pinLevel == None) {
            panic("button_init: pinLevel 不能为空")
        }
        this.buttonLevel = if (activeLevel == 0) { 1 } else { 0 }
        this.halButtonLevel = pinLevel
        this.activeLevel = activeLevel
        this.buttonId = buttonId
        this.userData = userData
        this.state = ButtonState.IDLE
        this.event = ButtonEvent.NONE_PRESS
        this.callbacks = Array<BtnCallback<T>?>(EVENT_COUNT, { _ => None })
    }

    override func fireCallback(event: ButtonEvent): Unit {
        let eventIdx = event as Int64
        if (eventIdx >= 0 && eventIdx < this.callbacks.size) {
            match (this.callbacks[eventIdx]) {
                case Some(cb) => cb(this)
                case None => {}
            }
        }
    }
}

// 活跃按钮列表使用基类类型
var activeButtons: ArrayList<ButtonBase> = ArrayList<ButtonBase>()
```

这样：

- `activeButtons` 统一存放 `ButtonBase` 类型的对象
- 遍历时调用 `btn.fireCallback(event)`，多态分发到正确的泛型实现
- `buttonStart<T>` / `buttonStop<T>` 操作的是 `ButtonBase` 类型，无类型冲突

## 9. 第七步：线程安全支持

### 9.1 互斥锁接口

原 C 代码通过宏 `MULTIBUTTON_LOCK()` / `MULTIBUTTON_UNLOCK()` 实现可选锁支持。仓颉版使用接口 + 策略模式实现：

```cangjie
// src/multi_button.cj 中继续

// ============================================================
// 线程安全接口
// ============================================================

/**
 * 互斥锁接口
 * RTOS 环境实现此接口提供真实的锁操作；
 * 裸机环境使用 NoopLock（零开销）。
 */
interface MutexLock {
    func lock(): Unit
    func unlock(): Unit
}

/**
 * 空锁实现（裸机/单线程环境，零开销）
 */
class NoopLock : MutexLock {
    func lock(): Unit { /* 空操作 */ }
    func unlock(): Unit { /* 空操作 */ }
}

/**
 * 全局锁实例（默认空锁，RTOS 环境可替换）
 */
var globalLock: MutexLock = NoopLock()

/**
 * 设置线程安全锁（RTOS 环境初始化时调用）
 */
func setGlobalLock(lock: MutexLock): Unit {
    globalLock = lock
}

// ============================================================
// 带锁保护的 buttonTicks（线程安全版本）
// ============================================================

/**
 * 驱动所有按钮（带锁保护版本）
 *
 * 注意：回调在锁外执行，因此回调中可以安全调用 buttonStart/buttonStop。
 */
func buttonTicks(): Unit {
    // 先取快照（在锁外执行回调是安全的，因为 next 指针已缓存）
    globalLock.lock()
    let snapshot = ArrayList<ButtonBase>(activeButtons)  // 浅拷贝快照
    globalLock.unlock()

    for (btn in snapshot) {
        handleButton(btn)
    }
}

// buttonStart / buttonStop 内部加锁：
// 已在第 7.1 节实现，此处为线程安全增强版

func buttonStartThreadSafe<T>(handle: Button<T>?): Int64 {
    if (handle == None) {
        return -2
    }

    let btn = handle as Button<T>

    globalLock.lock()
    defer { globalLock.unlock() }

    for (existing in activeButtons) {
        if (existing as Object == btn as Object) {
            return -1
        }
    }

    activeButtons.append(btn as ButtonBase)
    return 0
}

func buttonStopThreadSafe<T>(handle: Button<T>?): Unit {
    if (handle == None) {
        return
    }

    let btn = handle as Button<T>

    globalLock.lock()
    defer { globalLock.unlock() }

    var idx = 0
    while (idx < activeButtons.size) {
        if (activeButtons[idx] as Object == btn as Object) {
            activeButtons.remove(idx)
            btn.next = None
            return
        }
        idx += 1
    }
}
```

## 14. 注意事项与常见问题

### 14.1 行为保真度

移植时必须保持与原 C 库 100% 行为一致：

1. **消抖计数器：** 必须在连续 `DEBOUNCE_TICKS` 次读到相同新电平后才更新 `buttonLevel`。
2. **Tick 饱和处理：** 原 C 使用 `if (handle->ticks < UINT16_MAX)` 阻止溢出，仓颉版使用 `if (handle.ticks < 65535)`。
3. **长按触发只一次：** `LONG_PRESS_START` 只在从 PRESS 状态首次进入 LONG_HOLD 时触发一次，不应重复触发。
4. **RELEASE → REPEAT：** 只有在 `ticks < SHORT_TICKS` 时重新按下才进入 REPEAT 状态。
5. **REPEAT → PRESS 重置：** 在 REPEAT 状态按下太久，必须重置 `ticks = 0` 和 `repeat = 0`。
6. **LONG_PRESS_HOLD 高频：** 该事件在每个 tick 触发（默认 5ms = 200Hz），回调中需要自行节流。

### 14.2 内存管理


| 原 C                         | 仓颉版考虑                          |
| ---------------------------- | ----------------------------------- |
| 静态分配`static Button btn1` | 模块级`let btn1 = Button<...>(...)` |
| 手动`memset` 清零            | 构造函数完整初始化                  |
| `malloc` 动态分配            | 仓颉 GC / 引用计数自动管理          |
| 手动链表指针管理             | 可选`ArrayList` 或保持手动链表      |
| 无堆分配（嵌入式友好）       | 优先静态分配，避免 GC 抖动          |

### 14.3 嵌入式适配

1. **无动态内存：** 如果目标 MCU 不支持堆分配，应使用静态分配的 `Button` 对象数组而非 `ArrayList`。
2. **中断上下文：** `buttonTicks()` 在 ISR 中调用时，回调函数必须极短且无阻塞操作。
3. **位域紧凑存储：** 如果 RAM 小于 2KB，应实现方案 B（手动位操作）压缩每个按钮到 ~6 字节。
4. **FFI 对接：** 仓颉调用 C HAL 函数时使用 FFI：
   ```cangjie
   @Foreign("c")
   func HAL_GPIO_ReadPin(port: Int64, pin: Int64): Int64
   ```

### 14.4 替代设计选择


| 决策点     | 选项 A（推荐）                   | 选项 B（备选）                      |
| ---------- | -------------------------------- | ----------------------------------- |
| 链表存储   | `ArrayList<ButtonBase>`          | 手动`ButtonBase?` 单向链表          |
| 泛型上下文 | `class Button<T>`                | `class Button` + `Any?` userData    |
| 回调存储   | `Array<BtnCallback<T>?>`         | `HashMap<ButtonEvent, BtnCallback>` |
| 状态处理器 | 独立函数（`handleIdleState` 等） | 状态模式（多态类）                  |
| 线程安全   | 接口 + 策略                      | 编译期 feature flag                 |
